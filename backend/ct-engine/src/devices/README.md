# PC-direct device modules (offline candidate)

Each device module owns one physical role and exposes message proxies from mod.rs. Hardware acceptance remains BLOCKED; tests use scripted transports, never real devices.

## xray/

- moxtek.rs owns the raw binary protocol, requested setpoints, measured readback and verified OFF. A complete monitoring pair (0x43 + 0x80) shares at most ten seconds, bounded by the absolute output deadline. OFF keeps one second per transaction. No command is replayed; invalid packets and exhausted budgets close the beam. A typed monitoring read timeout with verified OFF retains a monotonic interruption record; scan.rs may requalify two fresh OFF pairs 500 ms apart, frozen camera settings and Nano evidence before resuming. The device layer never automatically enables output. Protocol/driver/interlock/temperature/unknown-OFF faults do not qualify.
- transport.rs accumulates fragmented replies across 50 ms cancellable read slices. Timeouts distinguish received bytes and elapsed/budget milliseconds; real driver errors fail immediately. A short OS read timeout alone does not discard a pending reply.
- worker.rs is the single serial owner for manual and scan actions, cached health, priority OFF, caller/worker cancellation, independent monitoring and hard output deadlines. Scan and background emission checks share only a fully verified pair less than 250 ms old in the current generation; mutations, OFF and faults invalidate it. Priority OFF cancels both queued operations and autonomous polling. A bounded diagnostic queue feeds domain logs and scan.log. Confirmed OFF preserves the two-second re-enable gate across all callers.
- Initial discovery failure before any source session or port evidence is a rejected connection attempt; it does not trigger Nano warning or a global Stop. Formerly owned sources and any transport/protocol/OFF failure retain fail-closed cleanup. The domain observer logs changed cached health failures once instead of on every engine tick. Measured telemetry advisory episodes log once in both scan and manual observers; varying numeric samples remain in health and do not evict capture receipts. A new episode, changed setpoints or a different diagnostic still logs.

## camera/

- actor.rs owns creation/use/release of COM objects on its dedicated thread and exposes a Send message proxy. wpd.rs independently implements Microsoft MTP extensions; ptp.rs validates bounded datasets.
- nikon.rs contains necessary MIT D7100 operations and property readback, exact native timed shutters, Live View/AF and supported focus steps. Other models receive only described standard capabilities; host capture stays disabled without proof.
- capture.rs binds exclusive session/operation events, separates ExposureEnded from object/transfer/file completion, verifies complete NEF/length/hash, and commits atomically under cancellation. Elapsed time or file appearance never proves exposure end.
- live_view.rs holds validated latest-only JPEG envelopes and a random user-ACL pipe. Images never enter JSONL; Stop/session changes/loss revoke live identity. See camera/README.md and THIRD-PARTY-NOTICES.md for event and hardware limits.
- storage.rs parses strict GetStorageIDs/GetStorageInfo/GetObjectHandles datasets and plans writable SD-card capacity offline; ptp.rs validates card-resident ObjectInfo NEF metadata with a separate strict parser that does not relax the RAM tolerance. Neither path contacts a device, and no card conclusion is drawn without hardware acceptance.
- card_capture.rs triggers one standard InitiateCapture (0x100E, never the private SDRAM code) and associates exactly one ObjectAdded object and one CaptureCompleteCard completion with it under a frozen card profile. The only object read is bounded GetObjectInfo metadata: no image, partial-object or thumbnail read, no local file and no hash. StoreFull overflow needs a planned second storage plus the advertised events; duplicates, unplanned storages, StoreRemoved, RAM evidence, changed sessions and trailing events refuse the receipt and leave the capture fail-closed.
- L1 card early release is enabled by default in scan preparation and can be disabled per scan. The explicit card capture plan carries that choice; the legacy environment switch remains available for component acceptance. Only the first operation-local D1A4 bit15 1->0 emits `EarlyExposureEnded`; scan.rs validates session/operation, releases a nonfinal hold and prefetches the next monitored MOVE, then waits for the current durable receipt before the next trigger. Receipt evidence, schemas and CARD_READ_ONLY admission stay unchanged. Missing early evidence follows the default path; duplicate events do nothing; post-release failures retain unresolved intents without re-shot or acquisition credit. The original diagnostic-only switch remains independent. See camera/README.md for rollback and promotion requirements.
- card_import.rs is the only place that ever requests the card objects' image bytes, and only for a task the registry already retains as `acquired_pending_import`. It re-enumerates storages, handles and ObjectInfo through the same single camera owner, binds each record to exactly one object by storage id, source file name, size and capture date (handles and storage ids are never a permanent identity), downloads with a bounded GetObject, validates the complete D7100 NEF, streams SHA-256 while staging, commits atomically without overwriting into the existing frames/references layout, resumes by re-verifying committed files, and seals the schema-4 manifest (`dataStatus=verified`, `completed=true`) only when every record is verified. After the complete local seal it re-hashes all files, writes a separate card-cleanup.json journal, and deletes only exact receipt-bound SD objects through the same owner, with immediate metadata re-read and fresh absence confirmation. A cleanup failure/cancel preserves the verified manifest and retained task; retry re-enumerates remaining objects without downloading or shooting again. Unrelated card files remain intact; real USB import/deletion semantics remain hardware acceptance items.

## turntable/

- nano.rs owns identity, serial worker, heartbeat, HOME, advertised no-motion RESTORE_REFERENCE, warning, same-ID CAPTURE_DONE and priority STOP; cancelled epochs cannot admit late motion/rearm/reference restoration. Checkpoint and operator confirmation gates remain in device_controls.rs. One ordinary move reads exactly two STATUS frames on the serial owner (the pre-plan source freshness check and the single post-`READY_TO_CAPTURE` CAPTURE_HOLD read); `execute_plan` returns that already-qualified `CAPTURE_HOLD` evidence as `MoveOutcome`, so the coordinator verifies the plan/ticket and the nominal view angle without a third read. Any later wait still rereads, and a wrong ticket, drifted position or reused IDLE status is refused.
- planner.rs verifies fixed 8/96000 scaling and plans negative MOVE_REL from confirmed unwrapped pulses. Arrival and matching release must reach IDLE. Ordinary reverse/multiple turns are rejected; HOME retains the firmware's bounded retreat.
- firmware/rts9060_nano retains the recovered source provenance and pins the current 2.1.1 reference-recovery candidate for source rebuild and real-source host harness. VERSION/BUILD and offline tests do not certify installed flash or physical direction/accuracy.

Device modules do not call one another. scan.rs orders projection transactions; device_controls.rs owns independent HOME and all-device safety decisions. ct-engine remains the only domain authority.
