### 当前可做的准备

1. **保留完整任务目录。** 采集结束且文件不再写入后，备份 `<savePath>/<taskId>/` 整个目录，包含 `manifest.json`、`acquisition.csv` 和 `frames/` 中的原始 NEF。`savePath` 是保存根目录，`taskId` 是该次采集任务标识；未来导入的对象是任务目录，不是单张图片，也不是混有多次采集的保存根目录。
2. **不改动原始数据。** 不重命名投影、不手工调整索引或角度、不把 `completed` 改为 `true`，也不使用 JPEG、截图或经过照片增强的图像替换 NEF。备份时保留目录结构和清单，单独留存后续处理结果。
3. **整理真实几何资料。** 准备束型、扫描轨迹、有效探测器像素、旋转中心、坐标方向，以及适用的源—物距、源—探测器距。记录单位和测量/校准来源；未知项写“未知”，不要抄设备展示场景里的数值。
4. **整理已有校准资料。** 收集与投影条件匹配的暗场、平场、坏点/畸变和几何校准信息。暗场用于描述无入射信号时的响应，平场用于描述无样品时的参考响应；这些解释不是设备操作步骤。本指南不授权补拍校准、连接设备或开束。
5. **记录计算环境。** Windows 版本、可用内存、显卡/显存、驱动及可用磁盘空间。尚未选定 backend，因此现在不要求安装 Python、CUDA、ASTRA 或 TIGRE。

完成这些准备只能说明数据资料已整理，不能证明已经可以重构。正式就绪检查还需要验证文件、RAW 解码、几何与校准是否匹配。

### 默认重构流程（功能实现后）

| 步骤 | 使用者怎么做 | 应得到的反馈 |
| --- | --- | --- |
| 1. 选择数据 | 选择一次已结束采集的任务目录 | 扫描标识、帧数、源数据完整性及缺项报告 |
| 2. 补充资料 | 引用相应几何/校准资料；手动补充时注明来源和单位 | 新的数据集修订，不回写原始采集清单；缺必要资料则保持阻断 |
| 3. 选择算法 | 从兼容算法中选一个已验证的基线 | 平行束可评估 FBP，圆轨迹锥束可评估 FDK；没有兼容算法时说明原因，不自动套用错误几何 |
| 4. 配置参数 | 确认预处理方式、输出范围、体素大小及算法专属参数 | 参数合法性、输入阶段、RAM/VRAM 与磁盘估算；传统算法通常不需要模型权重 |
| 5. 提交任务 | 确认数据修订、算法版本、有效参数和结果位置 | 快速返回任务 ID；依次展示验证、预处理/计算、结果校验等阶段，不阻塞 App |
| 6. 等待或取消 | 查看阶段和诊断；不需要结果时请求取消 | 取消请求后可能短暂显示 `cancelling`；只有退出与临时输出处置完成后才是 `cancelled` |
| 7. 查看结果 | 仅打开主机校验并发布成功的结果 | 科学体数据、可用预览、质量警告及完整运行记录 |
| 8. 比较方法 | 固定同一数据集修订，改变一个算法或参数后提交新任务 | 新任务和新结果，不覆盖前一次；比较时核对坐标、体素大小和数值单位 |

**初期设计不支持边采集边重构。** 算法取消不是设备 STOP；设备停止与关束仍走原控制链。算法进度 100%、进程退出或出现结果文件都不等于任务成功，最终以主机校验后的 `succeeded` 为准。

### 参数怎么填

| 参数类别 | 基本原则 |
| --- | --- |
| 几何与校准 | 来自实测、校准或可追溯资料，不是“调到图像好看”的参数；改变后应创建新数据集修订 |
| 输入阶段 | NEF 原始数据、线性强度、归一化透射率、线积分不能混用；已经校正/取负对数的数据不可重复处理 |
| 输出体素大小 | 决定输出网格采样间距，不等于设备真实分辨率；更小通常增加存储与计算量，不保证出现更多真实细节 |
| 输出范围/尺寸 | 需与对象和几何一致；修改 ROI、裁剪或重采样要保留正确空间变换 |
| 滤波核/迭代次数 | 只在所选算法支持时出现；优先使用经过验证的插件默认值，再逐项比较，避免同时修改多个变量 |
| 模型与推理参数 | 仅学习型插件需要；模型必须匹配适配器、输入通道、归一化和适用域。学习率、训练轮次不能替代训练后的权重 |

目前没有已验证的生产默认值。不要把第 3 节合成测试样例中的尺寸、像素或角度当作真实设备参数。

### 结果怎么看、要保存什么

- **先看科学体的切片和空间信息。** 检查方向、尺寸、中心、体素间距，以及截断、条纹、环状伪影等问题，再看三维预览。预览“看起来像物体”不能单独证明重构正确。
- **科学体用于继续分析。** 三维预览可能降采样；STL 等表面网格只是派生产物，不能替代科学体用于材料分析。
- **保留整个结果包及来源资料。** 至少保留科学产物、结果清单、有效参数、插件/模型版本、质量报告和输入/校准的身份信息；原始输入与校准文件也需另行保留，仅有哈希不能恢复数据。
- **不要过度解释灰度。** 未经对应校准不能将数值称作 HU、密度或材料成分；材料标签是模型在其适用域内的判断，不是独立物性测量。
- **失败/取消的临时文件不是正式结果。** 不手工把它们移到成功目录，也不要自行修改任务状态。复算提交新任务，保留原失败记录用于诊断。

科学体主格式和结果包实际文件布局尚待选型，当前不提供可直接导入的结果样例。

### 自定义扩展怎么准备

| 你的情况 | 应准备什么 | 不需要做什么 |
| --- | --- | --- |
| 想用基本 CT 重构 | 完整数据、几何/校准资料和兼容的基线插件 | 不需要提供训练权重或训练超参数 |
| 已有符合适配器的训练模型 | 模型权重、模型 ID/版本、兼容适配器版本、输入输出张量约定、预处理、类别说明、适用域、许可和验证结果 | 不需要为每个模型重新编写 App 界面；但必须满足已有能力类型 |
| 有全新算法、网络或特殊算子 | 完整插件：声明清单、运行入口、锁定依赖、参数 schema、输入输出约定、资源要求、许可及离线验证样例 | 不把算法代码塞入前端，也不直接访问设备 |

计划中的接入顺序是：**准备包 → 读取并校验声明 → 确认来源与信任 → 经确认配置运行环境 → 检查数据兼容性 → 按同一任务流程运行。** 自动发现不等于自动执行，不能只把脚本或 `.pth`/`.onnx` 文件复制到 `algorithm-plugins/` 就认为安装完成。

插件协议与安装机制尚未冻结：现在可整理交付资料，但不要据此创建安装目录或运行未经审核的包。详细字段见第 3 节；模型、训练与材料分析的区别见第 4.4 节。

### 常见问题

以下提示及错误码是拟议行为，当前不是已上线的错误界面。

| 问题或提示 | 应怎么处理 |
| --- | --- |
| 当前 App 找不到插件安装/运行入口 | 属于尚未实现的能力，不是安装失败；本指南不提供不存在的菜单或命令 |
| 文件齐全，却提示 `GEOMETRY_REQUIRED` / `CALIBRATION_REQUIRED` | 补齐有来源的几何/校准；文件完整不等于满足科学计算条件 |
| `DATASET_INCOMPLETE` / `DATA_CORRUPT` / `INPUT_CHANGED` | 核对源任务是否结束、帧数、原始备份和校验；不要改清单或忽略哈希强行运行 |
| `INPUT_STAGE_MISMATCH` / `PREPROCESS_ALREADY_APPLIED` | 核对数据所处阶段，选择兼容的处理链，避免重复校正和取负对数 |
| 没有兼容算法或 `MODEL_INCOMPATIBLE` | 核对束型/轨迹、数据阶段、模型适配器和输入规范；不能通过重命名文件解决 |
| `RESOURCE_UNAVAILABLE` / `DISK_FULL` | 选择具备所需资源的环境，或显式配置更低输出规模后建立新任务；不要删除原始数据腾空间 |
| `JOB_TIMEOUT` / `PLUGIN_FAILED` | 保留任务 ID、插件版本、阶段和错误摘要，检查批准的运行环境；不要无限重试或改成成功 |
| `OUTPUT_INVALID` / `PUBLISH_FAILED` | 检查诊断、磁盘、写入权限和文件占用；部分输出不作为有效结果使用 |
| 重启后任务为 `interrupted` | 先查看已有记录及发布检查结论；未完成任务不会自动续算，重新计算使用新任务 ID |

## 1. 定位、范围与实施阶段

将 Algorithm Plugin 定位为**标准化离线计算接口**，不是任意权重文件加载器。默认 CT 重构与用户插件使用相同的数据集、插件、任务和结果契约；后续分割、材料分类和模型推理复用同一契约，不为每个算法改 App 业务代码。

**首版目标：**选择已结束采集 → 检查数据条件 → 选择兼容算法 → 配置参数 → 异步计算/取消 → 查看科学体数据及展示结果。

**首版不做：**训练平台、插件市场、可视化节点编辑器、在线重构、边采集边重构、不可信代码执行环境，也不创建占位计算结果。

| 阶段 | 内容 | 完成判据 |
| --- | --- | --- |
| M0 契约冻结 | 四份契约的最小字段集、版本与错误语义定型 | 有可执行类型/校验与正例反例，不依赖运行插件 |
| M1 导入与就绪检查 | 只读导入任务目录，验证文件/哈希/索引/角度，输出缺项报告 | 正常数据可识别；缺项、损坏、变更均有明确诊断，不因文件齐全显示“可重建” |
| M2 任务监督 | 提交、状态、取消、失败、重启恢复、结果发布校验 | 长任务不阻塞控制链；失败/取消/未校验产物不发布 |
| M3 基线算法闭环 | 单一基线算法 + 合成模体数值验证 | 已知真值下满足预定误差与可复现判据，不看三维截图 |
| M4 真实数据接入 | NEF 解码、暗/平场与负对数链、科学体产出、最小 UI | 缺必要校准时阻断；结果保留空间语义与溯源 |

M0–M2 不连接设备、不安装算法依赖即可完成；M3 起才涉及 backend 选型与安装审批。

### 必须补齐或显式阻断的信息

- **几何：**束型/轨迹、源—物距与源—探测器距（适用时）、有效探测器像素尺寸、旋转轴/中心、探测器姿态与偏移、坐标定义与单位。相机像元不自动等于闪烁屏有效像素。
- **投影：**索引与角度一一对应、角度符号/单位/来源、有效 ROI、尺寸/位深、线性强度生成方式、曝光与增益条件；不从文件名猜测角度。
- **校准：**暗场、平场、坏点、畸变、校准版本与适用条件；不适用需给出方法依据，不能用空值表示“已校准”。
- **完整性：**采集已结束且不再写入、预期帧数、无重复/缺失索引、文件可解码、校验一致。仅 `completed=true` 不足以证明可重构。
- **来源：**手工补充须有操作者声明、来源、单位、时间和不确定性；未知保留未知，不得自动填“典型值”。

### 已知规范差异

`docs/architecture/README.md` 的“投影事务”（47–59 行）描述逐帧关束后提交；当前 `scan.rs`（424–491、516–569 行）支持连续出束块，在传输开始后释放并按时限/末帧/暂停条件关束。本文只登记差异，不修改或认可设备行为；计算启动门禁须由引擎确认采集已结束、文件不再写入且控制状态允许，不能从图片存在推断设备安全。

## 3. 四份契约评审约定

四份契约分别用 `contract` 标识与 `schemaVersion`；插件执行协议另有 `protocolVersion`，不与设备 JSONL 协议混用。草案目标版本 `1.0`，主版本不兼容必须拒绝；次版本只允许新增可选能力，未知主版本/必需能力/枚举值拒绝而非猜测。

**通用语义：**数值有限且满足范围，缺失/`null`/0 不互相替代；时间为含时区 UTC，相对路径按所在清单根解析；文件引用描述角色、相对路径、字节数与 SHA-256，不接受插件提供的主机绝对路径、URL 或 shell 命令；参数默认值由主机解析、验证并固化；未知字段拒绝，扩展放入命名空间的 `extensions` 并用 `requiredCapabilities` 声明。就绪结论不是数据集自证字段，由主机按数据集/插件/参数/模型实时产生 `ready/blocked` 与问题列表。

### 3.1 数据集 `ct.dataset`

| 字段组 | 内容与校验 |
| --- | --- |
| 身份与来源 | `datasetId`、`revision`、`sourceScanId`、`sourceManifestHash`、`importedAt`、`parentArtifacts`；已发布修订不可覆盖 |
| 文件清单 | `files` 角色/大小/哈希；`projections` 按显式索引引用文件与 `angleRad`，声明 `angleSource`（planned/encoder/calibrated）及证据 |
| 数组约定 | `shape`、`dtype`、`axisOrder`、存储格式、索引基准；逻辑轴 `[view,v,u]`，从 0 开始 |
| 数值阶段 | `dataStage`：`raw_sensor / linear_intensity / normalized_transmission / line_integral`；原始 NEF 无通用灰度语义，必须经已记录转换 |
| 几何 | `geometry.type`（首批 `parallel`/`cone_circular`）、`coordinateFrame`、旋转轴与中心、角度零位/正方向、有效像素、每视图或参数化探测器姿态；锥束须含源位置与距离。长度 mm、角度 rad |
| 校准 | 暗场/平场/坏点/畸变引用与哈希、适用曝光/增益/能谱条件、生成方法；几何校准记录版本、来源与不确定性 |
| 处理历史 | 父产物、步骤 ID、插件/版本、有效参数、输入输出阶段；不得用 `corrected=true` 隐藏顺序 |
| 完整性 | 采集已结束的引擎证据或离线导入声明、预期/实际数量、文件验证报告、已知警告 |

坐标必须可重现：右手物理坐标系；定义探测器 `(u=0,v=0)` 像素中心物理位置与 u/v 单位方向，角度按声明旋转轴的右手规则。裁剪/翻转/重采样须同步更新几何。负方向计划角度保留来源并显式变换映射，不擅自取绝对值。

旧目录通过只读适配读取 manifest v1，路径按任务根重新定位并核对文件身份；待源停止写入后验证数量/哈希/可解码性，必要时建立稳定快照并再次验证。补充信息写入新修订，不回写原始 NEF、manifest 或 CSV。首版不支持不完整采集的“尽力重构”。

### 3.2 插件 `ct.plugin`

| 字段组 | 内容与校验 |
| --- | --- |
| 身份与可信来源 | `pluginId`、`pluginVersion`、发布者、包内容哈希；哈希只证明一致性，执行需单独信任确认 |
| 协议与能力 | `supportedProtocols`、`requiredCapabilities`、`capabilities`（preprocess/reconstruct/segment/material_inference，不隐含训练） |
| 输入输出 | 具名端口：类型、数据阶段、几何、dtype、数量/可选性、必需校准、角度来源要求；输出声明科学体/标签/概率/网格 |
| 参数 | `parameterSchema`：类型、范围、单位、默认值、枚举、交叉约束与说明；禁止动态执行插件生成参数面板 |
| 运行入口 | `runtime`、受支持的 `entryPoint`、锁定依赖引用；执行器映射为可执行文件与参数数组，不拼 shell 字符串 |
| 资源与分发 | OS/架构、CPU/GPU backend、最低驱动/显存、估算方式、依赖与许可证、是否允许离线分发；缺硬件阻断，不静默换算法 |
| 模型 | 是否需 `modelRef`、支持的格式/适配器与张量规范；传统算法允许无模型 |

发现阶段只读取有大小限制的清单，不导入模块、不执行安装钩子、不下载依赖；重名 ID/版本但哈希不同报告冲突。兼容列表不代表已授权运行。

### 3.3 任务 `ct.job`

| 字段组 | 内容与校验 |
| --- | --- |
| 身份与提交 | 主机生成 `jobId`，`idempotencyKey` 标识一次提交；同键同内容返回原任务，同键异内容拒绝；重算是新任务，`retryOf` 可关联 |
| 固定输入 | 数据集 ID/修订与清单哈希、插件版本/包哈希、可选模型版本/哈希；运行前再次核对 |
| 配置 | `effectiveParameters` 固化默认值；`requestedResources` 与主机 `resourceBudget` 区分；主机分配独占输出根 |
| 生命周期 | `state`/`stage`、时间、阶段进度、心跳、错误、取消请求；独立于扫描 `phase` |
| 溯源 | 随机种子（适用时）、解释器/库/backend/驱动版本、硬件概况、日志引用、警告、结果清单引用；不声称 GPU 逐位确定 |

状态顺序 `queued → validating → running → verifying → succeeded`；校验/执行/发布可进入 `failed`。运行中取消进入 `cancelling`，进程树退出且清理临时输出后进入 `cancelled`；重启发现未结束任务标 `interrupted`，不自动重跑或冒充成功。

- 提交只做有界检查并快速返回任务 ID；大文件校验在验证阶段异步执行。状态查询只返回有界摘要，事件用 `jobId + sequence + stage + timestamp` 去重。
- worker stdout 只输出版本化结构化事件，stderr 用于有界诊断；日志与进度限速、限长、限总量。长阶段可报未知总量，不伪造匀速百分比；worker 报 100% 或退出码 0 都不等于主机成功。
- 启动超时、心跳超时、阶段无进展、总运行上限分别配置；取消先协作请求，宽限到期终止进程树，不能终止设备引擎；晚到成功事件不得覆盖已接受的取消。
- 取消与发布由同一监督者串行裁决；非法跳转、错误任务 ID、重复终态事件不改权威状态。
- 算法失败只更新计算任务与告警，不伪造采集故障或安全状态；STOP、关束、断开仍走原控制链。不存在调用设备的插件命令。

### 3.4 结果 `ct.result`

| 字段组 | 内容与校验 |
| --- | --- |
| 来源 | `resultId`、`jobId`、输入/校准修订与哈希、插件/模型身份、有效参数、环境、处理历史与参考坐标系 |
| 科学产物 | `artifacts` 的 ID、类型、相对路径、字节/哈希、格式、shape/dtype/轴顺序、单位与 `valueMeaning`；逻辑轴 `[z,y,x]`，物理分量 `[x,y,z]` |
| 空间语义 | `spacingMm`、`originMm`、`direction`、`coordinateFrame`；位置为 origin + direction × diag(spacing) × [x,y,z]，origin 是首体素中心；三者不得与文件头矛盾 |
| 派生产物 | 展示体、缩略图、网格引用科学父产物及降采样/分割变换；标签有类别 ID/背景/未知约定，概率有类别轴与范围说明 |
| 质量与发布 | `qualityWarnings`、检查报告、完成时间、`publicationState`；worker 只提供候选结果，主机校验后的发布记录才是成功依据 |

未验证绝对衰减尺度时标 `arbitrary_unit`；即使按 1/mm 输出也须说明标定与多色性限制；未经校准不得标 HU、密度或材料成分。结果先写任务私有临时区，主机核对清单、允许文件、可解码性、维度/方向/单位、有限值与哈希后再发布到唯一结果位置，禁止覆盖旧结果或源采集。发布临时区与目标应在同一受支持文件系统，Windows 下句柄占用、杀毒软件、目标冲突、掉电/重启恢复须实测；重启对账后只有完整且验证通过的提交记录恢复为成功，其余隔离并标记中断。

### 3.5 评审样例与统一错误语义

样例仅用于评审，ID/版本/数值为合成测试值，不是本机设备参数；实施时补齐全字段正/反例并交给正式 schema 与语义校验器。

| 契约 | 正例 | 缺项/冲突 | 不兼容 |
| --- | --- | --- | --- |
| 数据集 | 合成 `phantom-parallel` 修订 1：180 个 `[v=64,u=64]` float32 线积分投影，角度 kπ/180 明确关联，1 mm 有效采样、完整坐标与来源，文件验证通过 | 锥束缺源位置/有效像素/几何校准：`GEOMETRY_REQUIRED`；intensity 送入只收 line_integral 的插件：`INPUT_STAGE_MISMATCH` | `schemaVersion=2.0` 而主机只支持 1.x：`SCHEMA_UNSUPPORTED` |
| 插件 | `example.parallel-fbp` 0.1.0，协议 1.0，声明 parallel + line_integral 输入、科学体输出、有限枚举 filter、已批准入口与环境/许可证 | 缺入口或参数 schema：`MANIFEST_INVALID`；同版本不同包内容：`PLUGIN_CONFLICT` | 仅支持协议 2.0：`PROTOCOL_UNSUPPORTED` |
| 任务 | `job-example-1` 绑定上述精确修订、插件包摘要、显式 filter 与输出网格，模型为空，主机分配新输出根 | 输入哈希不符：`INPUT_CHANGED`；缺必需参数：`PARAMETER_INVALID`；同键换输入：`IDEMPOTENCY_CONFLICT` | 未知必需能力或主版本：`CAPABILITY_UNSUPPORTED`/`SCHEMA_UNSUPPORTED` |
| 结果 | `result-example-1` 声明 `[64,64,64]` 科学体、`[1,1,1]` mm 间距、单位方向矩阵、`[-31.5,-31.5,-31.5]` mm 首体素中心与验证通过的文件清单 | 缺 spacing/direction、文件头与清单矛盾、NaN 体素或只有 STL：`OUTPUT_INVALID` | 不支持的必需格式或主版本：`FORMAT_UNSUPPORTED`/`SCHEMA_UNSUPPORTED` |

统一错误至少携带 `code`、`stage`、可公开消息、字段/产物定位、`retryable` 与建议操作；未知错误统一为 `PLUGIN_FAILED` 并保留受限诊断，不用成功或空数组兜底。

| 类别 | 代表码 | 行为 |
| --- | --- | --- |
| 数据未就绪 | `DATASET_INCOMPLETE`、`CALIBRATION_REQUIRED`、`DATA_CORRUPT`、`GEOMETRY_UNSUPPORTED` | 阻断并指出缺项；不自动采集校准、不补典型几何 |
| 语义/配置 | `INPUT_STAGE_MISMATCH`、`PREPROCESS_ALREADY_APPLIED`、`PARAMETER_INVALID`、`MODEL_INCOMPATIBLE` | 不启动计算；修正输入或新建修订后重提 |
| 权限/路径 | `PLUGIN_UNTRUSTED`、`PATH_OUTSIDE_ROOT` | 拒绝执行/发布；不能换路径或隐式安装绕过 |
| 资源与运行 | `RESOURCE_UNAVAILABLE`、`DISK_FULL`、`PLUGIN_FAILED`、`JOB_TIMEOUT` | 保留原因、隔离部分输出；不自动换算法或无限重试 |
| 产物/恢复 | `OUTPUT_INVALID`、`PUBLISH_FAILED`、`JOB_INTERRUPTED` | 不标成功；重试是新任务，已发布结果不变 |

取消用终态 `cancelled` 表达，不伪装成插件错误或成功；`retryable` 只作提示，不授权自动运行插件或设备。

## 4. RAW、校正、算法与依赖门槛

### 4.1 固定初期处理链

原始 NEF → 经验证的线性强度 → 平暗场归一化 → 负对数投影 → 重构体 → 可选分析。已是线积分的输入跳过已完成步骤；流水线依据类型与历史决定，不按文件后缀或重复点击重新校正。

| 阶段 | 需明确并保存的决策 | 阻断条件 |
| --- | --- | --- |
| NEF 解码 | 解码器/版本、压缩与位深、Bayer/通道处理、黑/白电平、坏点、有效 ROI；禁止隐式 gamma、自动亮度、白平衡或照片增强 | 不能证明输出与入射响应线性；当前相机格式不受支持 |
| 探测成像映射 | 经闪烁屏/镜头采集时标定有效像素、畸变、ROI 到探测器坐标的变换；通道选取或去马赛克须有实验证据 | 把相机像元当有效探测器像元，或畸变未知且超出方法容许范围 |
| 暗场/平场 | 对应曝光/增益、能谱设定、温度等条件；多帧合成与漂移策略；科学数据与暗平场走一致解码路径 | 缺失必需校准、条件不匹配或无依据缩放 |
| 强度归一化 | T=(I−D)/(F−D)，保留有效掩膜与异常比例；区分相机黑电平校正与实测暗场，避免重复扣除 | F−D 非正、饱和、坏点或低信号比例超约定门槛 |
| 负对数 | p=−ln(T)，记录阈值、掩膜/插值策略与被处理比例 | 无约定异常处置、对 line_integral 再取对数、输出非有限值 |
| 其他校正 | 环伪影、束硬化、散射逐项作为可追踪步骤，说明假设与适用样品 | 校正改变物理含义却不更新语义/来源，或重复应用不支持步骤 |

异常策略与容差由数据验证和基线实验确定，草案不编造生产阈值；手动放宽必须成为新的有效参数与警告。校准缺失只提示所需证据，本模块不发起拍摄、转动或开束。

### 4.2 算法选择矩阵

| 方法 | 适用条件 | 局限 | 当前结论 |
| --- | --- | --- | --- |
| FBP 基线 | 平行束、已知像素/角度/旋转中心 | 不能把明显锥束当平行束；扇束须专门实现或有依据重排 | 若实测支持平行束再评估 |
| FDK 基线 | 已校准圆轨迹锥束、完整角覆盖与探测器几何 | 属近似方法；大锥角、截断、偏置轨迹受限；短扫描需明确覆盖与加权 | 若实际为圆轨迹锥束优先评估；非已选定依赖 |
| SIRT/CGLS 等 | 可匹配几何的前向/反投影器与收敛参数 | 计算/内存成本、噪声与正则化；稀疏角度不保证唯一恢复 | 第二阶段候选，首轮不铺开 |
| 学习型方法 | 明确训练域、结构、权重、输入规范与验证集 | 域偏移、伪结构与不确定性；视觉平滑不能替代科学准确性 | 后续插件，不取代未验证的物理基线 |

匹配必须覆盖束型、轨迹、角覆盖、截断、输入阶段、资源与模型适用域；无匹配算法即阻断，不为了有默认项选择近似错误的几何。

只定义评估问题，未做兼容性、许可证结论或安装验证。选定时须记录版本与官方许可/发行说明来源；不因名称熟悉就认定可随免安装版分发。

| 候选 | 用途 | 锁定前必须取得的证据 |
| --- | --- | --- |

| TIGRE | 锥束与迭代方法 | 轨迹/几何支持、CUDA 与部署方式、显存需求、数值基线、依赖分发条件 |

### 4.4 三类对象分离（模型与材料扩展）

| 对象 | 职责 | 接入限制 |
| --- | --- | --- |
| 算法插件 | 算法代码、网络构造/运行器、输入输出适配与参数约束 | 独立运行，统一任务协议；特殊算子/新网络用完整插件封装 |
| 已训练模型包 | 模型 ID/版本、权重与哈希、匹配的插件/适配器版本、张量布局/dtype/shape、归一化、输出解释、训练域与许可 | 只接受匹配适配器；禁止自动执行附带脚本或不受控反序列化 |
| 本次运行参数 | 滤波核、输出网格、迭代次数、阈值等有效配置 | 验证、冻结并写入溯源；学习率/轮次不等于训练后权重 |

适配器约定至少包括 batch/channel/spatial 轴、通道物理含义与单位、padding/重采样、可变尺寸、输出空间变换、类别表、背景与 unknown、概率语义与适用范围；重采样后标签/概率须映射回声明的物理坐标，标签不能默认用会混合类别的线性插值。

初期采用外部训练、App 内推理与结果比较；记录训练数据说明/许可、适用材料与能谱、验证指标、已知局限与不确定性。材料分类不等于物理材料分解：单能灰度受能谱、密度、束硬化与处理影响，当前采集契约未证明多能量/能谱条件成立；后续多能量扩展须显式绑定各数据集并要求能量条件、配准与校准，不能把重复普通扫描冒充多能量数据。材料结果不得回流为设备控制或安全判断依据。

## 5. 执行、安全与资源边界

- **所有权：**保留 React → Tauri → `ct-engine` 调用方向；拟由 `ct-engine` 内唯一计算任务监督者持有任务状态，外部 worker 执行重计算，Tauri 只转发，UI 只消费状态。任务监督是未来职责设计，本轮不创建服务或新进程目录。
- **互斥：**默认单计算任务且与生产采集不并发；未知控制状态不视为就绪；离线重构旧数据无需连接真实设备。
- **隔离：**不复用采集 `phase`；输入验证、校验和、进程等待、输出校验不得持有扫描/设备锁或阻塞命令处理；算法退出、取消、日志洪泛不得触发传输层超时误杀设备 sidecar。
- **命令分离：**设备 STOP/关束/断开与算法取消是不同命令，设备命令永不依赖算法响应；软件隔离不能替代屏蔽、联锁、急停和操作规程。
- **信任：**虚拟环境只隔离依赖，不隔离权限；首版仅允许人工信任的本地插件。路径检查覆盖绝对路径、`..`、UNC/设备路径、重解析点/junction、符号链接与 Windows 名称别名，仅字符串前缀比较不够；解包限制文件数与解压大小并拒绝越界成员。
- **副作用：**依赖安装、联网下载、执行第三方代码均为单独确认动作，不在扫描文件夹自动触发；结果不得含越界引用；清理只作用于本任务主机登记的临时根。
- **日志：**用任务 ID、插件 ID、阶段、错误码与短摘要定位，默认脱敏绝对路径与环境信息；不记录完整投影、模型权重或凭据；故障证据与科学结果分开保存，保留策略不得删除已发布结果。
- **预算：**设 P 投影数、D 每帧像素、V 体素数、b 字节、K 迭代次数，预处理约 O(PD)，直接反投影约 O(PV)，迭代约 K 倍增减（以实现实测为准）。提交前估算 RAM/VRAM、临时磁盘与结果空间并预留控制进程余量；运行时监控峰值、阶段耗时、I/O 与剩余磁盘。float32 的 512³ 约 0.5 GiB、1024³ 约 4 GiB，仅为单份数组，不是整机/显存最低要求。显存不足时阻断或让用户显式选择更低分辨率的新参数，禁止偷偷降采样科学输出。科学体只经文件/受控数据服务消费，UI IPC 只携带 ID、状态、路径与有界元数据。
- **UI：**沿用固定 1920×1080 与固定栏目不加内部滚动的规范，复杂配置放获批浮层/对话框；先做切片与空间信息检查，三维预览后置；现有设备场景不能当作重建结果查看器。
