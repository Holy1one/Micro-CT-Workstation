### 当前可做的准备

1. **保留完整任务目录。** 采集结束且文件不再写入后，备份 `<savePath>/<taskId>/` 整个目录，包含 `manifest.json`、`acquisition.csv` 和 `frames/` 中的原始 NEF。`savePath` 是保存根目录，`taskId` 是该次采集任务标识；未来导入的对象是任务目录，不是单张图片，也不是混有多次采集的保存根目录。
2. **不改动原始数据。** 不重命名投影、不手工调整索引或角度、不把 `completed` 改为 `true`，也不使用 JPEG、截图或经过照片增强的图像替换 NEF。备份时保留目录结构和清单，单独留存后续处理结果。
3. **整理真实几何资料。** 准备束型、扫描轨迹、有效探测器像素、旋转中心、坐标方向，以及适用的源—物距、源—探测器距。记录单位和测量/校准来源；未知项写“未知”，不要抄设备展示场景里的数值。
4. **整理已有校准资料。** 收集与投影条件匹配的暗场、平场、坏点/畸变和几何校准信息。暗场用于描述无入射信号时的响应，平场用于描述无样品时的参考响应；这些解释不是设备操作步骤。本指南不授权补拍校准、连接设备或开束。
5. **记录计算环境。** Windows 版本、可用内存、显卡/显存、驱动及可用磁盘空间。尚未选定 backend，因此现在不要求安装 Python、CUDA、ASTRA 或 TIGRE。

完成这些准备只能说明数据资料已整理，不能证明已经可以重构。正式就绪检查还需要验证文件、RAW 解码、几何与校准是否匹配。

### 默认重构流程（功能实现后）

| 步骤 | 使用者怎么做 | 应得到的反馈 |
| --- | --- | --- |
| 1. 选择数据 | 选择一次已结束采集的任务目录 | 扫描标识、帧数、源数据完整性及缺项报告 |
| 2. 补充资料 | 引用相应几何/校准资料；手动补充时注明来源和单位 | 新的数据集修订，不回写原始采集清单；缺必要资料则保持阻断 |
| 3. 选择算法 | 从兼容算法中选一个已验证的基线 | 平行束可评估 FBP，圆轨迹锥束可评估 FDK；没有兼容算法时说明原因，不自动套用错误几何 |
| 4. 配置参数 | 确认预处理方式、输出范围、体素大小及算法专属参数 | 参数合法性、输入阶段、RAM/VRAM 与磁盘估算；传统算法通常不需要模型权重 |
| 5. 提交任务 | 确认数据修订、算法版本、有效参数和结果位置 | 快速返回任务 ID；依次展示验证、预处理/计算、结果校验等阶段，不阻塞 App |
| 6. 等待或取消 | 查看阶段和诊断；不需要结果时请求取消 | 取消请求后可能短暂显示 `cancelling`；只有退出与临时输出处置完成后才是 `cancelled` |
| 7. 查看结果 | 仅打开主机校验并发布成功的结果 | 科学体数据、可用预览、质量警告及完整运行记录 |
| 8. 比较方法 | 固定同一数据集修订，改变一个算法或参数后提交新任务 | 新任务和新结果，不覆盖前一次；比较时核对坐标、体素大小和数值单位 |

**初期设计不支持边采集边重构。** 算法取消不是设备 STOP；设备停止与关束仍走原控制链。算法进度 100%、进程退出或出现结果文件都不等于任务成功，最终以主机校验后的 `succeeded` 为准。

### 参数怎么填

| 参数类别 | 基本原则 |
| --- | --- |
| 几何与校准 | 来自实测、校准或可追溯资料，不是“调到图像好看”的参数；改变后应创建新数据集修订 |
| 输入阶段 | NEF 原始数据、线性强度、归一化透射率、线积分不能混用；已经校正/取负对数的数据不可重复处理 |
| 输出体素大小 | 决定输出网格采样间距，不等于设备真实分辨率；更小通常增加存储与计算量，不保证出现更多真实细节 |
| 输出范围/尺寸 | 需与对象和几何一致；修改 ROI、裁剪或重采样要保留正确空间变换 |
| 滤波核/迭代次数 | 只在所选算法支持时出现；优先使用经过验证的插件默认值，再逐项比较，避免同时修改多个变量 |
| 模型与推理参数 | 仅学习型插件需要；模型必须匹配适配器、输入通道、归一化和适用域。学习率、训练轮次不能替代训练后的权重 |

目前没有已验证的生产默认值。不要把第 3 节合成测试样例中的尺寸、像素或角度当作真实设备参数。

### 结果怎么看、要保存什么

- **先看科学体的切片和空间信息。** 检查方向、尺寸、中心、体素间距，以及截断、条纹、环状伪影等问题，再看三维预览。预览“看起来像物体”不能单独证明重构正确。
- **科学体用于继续分析。** 三维预览可能降采样；STL 等表面网格只是派生产物，不能替代科学体用于材料分析。
- **保留整个结果包及来源资料。** 至少保留科学产物、结果清单、有效参数、插件/模型版本、质量报告和输入/校准的身份信息；原始输入与校准文件也需另行保留，仅有哈希不能恢复数据。
- **不要过度解释灰度。** 未经对应校准不能将数值称作 HU、密度或材料成分；材料标签是模型在其适用域内的判断，不是独立物性测量。
- **失败/取消的临时文件不是正式结果。** 不手工把它们移到成功目录，也不要自行修改任务状态。复算提交新任务，保留原失败记录用于诊断。

科学体主格式和结果包实际文件布局尚待选型，当前不提供可直接导入的结果样例。

### 自定义扩展怎么准备

| 你的情况 | 应准备什么 | 不需要做什么 |
| --- | --- | --- |
| 想用基本 CT 重构 | 完整数据、几何/校准资料和兼容的基线插件 | 不需要提供训练权重或训练超参数 |
| 已有符合适配器的训练模型 | 模型权重、模型 ID/版本、兼容适配器版本、输入输出张量约定、预处理、类别说明、适用域、许可和验证结果 | 不需要为每个模型重新编写 App 界面；但必须满足已有能力类型 |
| 有全新算法、网络或特殊算子 | 完整插件：声明清单、运行入口、锁定依赖、参数 schema、输入输出约定、资源要求、许可及离线验证样例 | 不把算法代码塞入前端，也不直接访问设备 |

计划中的接入顺序是：**准备包 → 读取并校验声明 → 确认来源与信任 → 经确认配置运行环境 → 检查数据兼容性 → 按同一任务流程运行。** 自动发现不等于自动执行，不能只把脚本或 `.pth`/`.onnx` 文件复制到 `algorithm-plugins/` 就认为安装完成。

插件协议与安装机制尚未冻结：现在可整理交付资料，但不要据此创建安装目录或运行未经审核的包。详细字段见第 3 节；模型、训练与材料分析的区别见第 5 节。

| 重启后任务为 `interrupted` | 先查看已有记录及发布检查结论；未完成任务不会自动续算，重新计算使用新任务 ID |

## 1. 定位与范围

将 Algorithm Plugin 定位为标准化的离线计算接口，而不是任意权重文件加载器。默认 CT 重构与用户插件使用相同的数据、能力、任务和结果契约；后续可接入分割、材料分类和模型推理，无须为每个算法修改 App 业务代码。

首个实现目标是：选择已结束的采集 → 检查数据条件 → 选择兼容算法 → 配置参数 → 异步计算/取消 → 查看科学体数据及展示结果。当前不建设训练平台、插件市场、可视化节点编辑器、在线重构或不可信代码执行环境；也不创建占位计算结果。

### 必须补齐或显式阻断的信息

- 几何：束型/轨迹、真实源—物距与源—探测器距（适用时）、有效探测器像素尺寸、旋转轴/中心、探测器姿态与偏移、坐标定义及单位。相机传感器像元不自动等于闪烁屏上的有效像素尺寸。
- 投影：索引与角度一一对应、角度符号/单位/来源、有效 ROI、尺寸/位深、线性强度生成方式、曝光与增益条件；不从文件名字典序猜测角度。
- 校准：暗场、平场、坏点、畸变、校准版本和适用条件。确实不适用时须给出方法依据，不能用空值表示“已校准”。
- 完整性：已结束且不再写入的采集、预期帧数、无重复/缺失索引、文件可解码、校验一致。仅 `completed=true` 不足以证明可重构。
- 来源：手工补充必须有操作者声明、来源、单位、时间和不确定性说明；未知内容保留未知。旧数据缺必要证据时阻断，不能自动填“典型值”。

### 已知规范差异：不以过期顺序推导算法边界

`docs/architecture/README.md` 的“投影事务”（47–59 行）及 `AGENTS.md` 的控制逻辑描述了逐帧关束后提交。当前 `scan.rs`（424–491、516–569 行）则支持连续出束块，在传输开始后调用 `release_projection_and_prefetch`，并按时限、末帧或暂停条件关束；并不保证每帧文件提交前已关束。

本文只记录差异，不修改或认可设备行为，不依赖上述文档的逐帧顺序判断计算就绪。后续实施前必须单独核对并同步相关规范。计算启动门禁须由引擎确认采集已结束、文件不再写入及当前控制状态允许；不能从图片存在推断设备安全。

## 3. 契约评审约定

以下是字段级设计，不改变采集 manifest v1；正式 schema、序列化类型和示例文件留到获准实施后。数据集、插件、任务和结果分别使用 `contract` 标识及 `schemaVersion`；插件执行协议另有 `protocolVersion`，不能与当前设备 JSONL 协议混用。

### 3.1 版本与通用语义

- 草案目标版本为 `1.0`，不承诺现在即可安装或执行。主版本变化表示不兼容；次版本只能添加不改变既有语义的可选能力。未知主版本、必需能力或枚举值必须拒绝，不尝试猜测兼容性。
- 插件软件版本、契约版本、运行协议版本、模型版本分别管理；精确版本和内容哈希进入运行记录。主机与插件无共同协议版本时返回 `PROTOCOL_UNSUPPORTED`。
- 正式 schema 候选采用 JSON Schema 2020-12。按明确支持的 schema 版本验证，未支持的次版本也须拒绝或使用经验证的显式降版适配，不因同主版本就自动接收。核心对象拒绝拼写错误/未知字段；扩展放入具命名空间的 `extensions`，并通过 `requiredCapabilities` 声明不可忽略的扩展。可选扩展可保留但不得偷偷影响计算。
- 数值必须有限且满足范围约束；缺失、`null`、0 不互相替代。未知值可保留用于导入诊断，但不满足计算必填条件。时间为含时区的 UTC 时间；相对路径按所在清单根解析。
- 所有文件引用描述角色、相对路径、字节数和 SHA-256；实际输入通过主机授权根定位。不接受插件提供的任意主机绝对路径、URL 或 shell 命令。参数默认值由主机解析、验证并固化，拒绝未知参数和非有限数值。
- 就绪结论不是数据集自证字段：主机根据数据集版本、插件版本、参数和模型实时产生 `ready / blocked` 及问题列表（`code`、字段定位、原因、补充方式）。算法变化后必须重新检查。

### 3.2 数据集契约：`ct.dataset`

| 字段组 | 内容与校验 |
| --- | --- |
| 身份与来源 | `datasetId`、`revision`、`sourceScanId`、`sourceManifestHash`、`importedAt`、`parentArtifacts`；同一 ID 的已发布修订不可覆盖，`importedAt` 不冒充采集开始时间 |
| 文件清单 | `files` 及其角色、大小/哈希；`projections` 按显式索引引用文件和 `angleRad`，声明 `angleSource`（planned/encoder/calibrated）及证据；记录实际反馈存在与否，不从计划角度合成反馈 |
| 数组约定 | `shape`、`dtype`、`axisOrder`、存储格式及索引基准；规范化投影逻辑轴为 `[view,v,u]`，索引从 0 开始；存储文件的排列由适配器明确映射 |
| 数值阶段 | `dataStage` 为 `raw_sensor / linear_intensity / normalized_transmission / line_integral`；原始 NEF 尚无通用灰度强度语义，必须经过已记录的转换 |
| 几何 | `geometry.type`（首批候选 parallel/cone_circular）、`coordinateFrame`、旋转轴与中心、角度零位/正方向、有效像素、每视图或参数化探测器姿态；锥束必须含源位置及适用距离。长度规范化为 mm、角度为 rad |
| 校准 | `calibrations`：暗场/平场/坏点/畸变引用、哈希、适用曝光/增益/能谱条件、生成方法；几何校准记录版本、来源及已知不确定性 |
| 处理历史 | `processingHistory`：父产物、步骤 ID、插件/版本、有效参数、输入输出阶段和校准引用；不得只用 `corrected=true` 隐藏处理顺序 |
| 完整性 | `sourceClosed` 的引擎证据或离线导入声明、预期/实际数量、文件验证报告和已知警告；导入声明不构成设备状态证据 |

坐标语义必须能重现：右手物理坐标系；定义探测器 `(u=0,v=0)` 像素中心的物理位置及 u/v 单位方向向量，角度按声明旋转轴的右手规则。裁剪、翻转、重采样必须同步更新几何，不能仅改变数组。导入当前负方向计划角度时保留来源，通过明确变换映射到规范坐标，而非擅自取绝对值。

旧采集目录通过只读适配读取 manifest v1；路径优先按任务根重新定位并核对文件身份，不盲信旧绝对路径。待源停止写入后验证数量/哈希/可解码性，必要时建立独立稳定快照并再次验证。补充信息写入新数据集修订，不回写原始 NEF、manifest 或 CSV。首版不支持不完整采集的“尽力重构”；将来如需开放，必须由插件显式声明支持且产生质量警告。

### 3.3 插件契约：`ct.plugin`

| 字段组 | 内容与校验 |
| --- | --- |
| 身份与可信来源 | `pluginId`、`pluginVersion`、名称、发布者、包内容哈希；哈希只证明一致性，不证明可信，允许执行需单独信任确认 |
| 协议与能力 | `supportedProtocols`、`requiredCapabilities`、`capabilities`；能力可为 preprocess/reconstruct/segment/material_inference，不隐含训练能力 |
| 输入和输出 | 带名称的输入端口：类型、数据阶段、几何、dtype、数量/是否可选、必需校准、角度来源要求；输出端口声明科学体/标签/概率/网格等类型；固定流程按类型匹配 |
| 参数 | `parameterSchema`：类型、范围、单位、默认值、枚举、交叉约束和说明；禁止动态执行插件来生成参数面板；不支持的 schema/UI 控件应明确拒绝而非漏掉参数 |
| 运行入口 | `runtime`、受支持的 `entryPoint` 描述、锁定依赖引用；执行器映射到批准的可执行文件和参数数组，不把清单内容拼为 shell 字符串 |
| 资源与分发 | OS/架构、CPU/GPU backend、最低驱动/显存、估算方式、依赖/许可证、是否允许离线分发；缺硬件时阻断，不静默切换到不同算法 |
| 模型 | 是否需要 `modelRef`、支持的模型格式/适配器和输入输出规范；传统算法允许无模型，不制造空权重包 |

发现阶段只读取有大小限制的清单，不导入 Python 模块，不执行安装钩子，不下载依赖。重名 ID/版本但哈希不同必须报告冲突，不能以目录扫描顺序覆盖。兼容插件列表也不代表运行已授权；升级按新包审查，不改写已完成任务的版本引用。

原有 `<plugin-venv>/python -m ct_worker run request.json` 可作为 Python 适配器的候选调用形式，不是已存在的入口；其他语言也可通过同一运行协议接入。默认算法不得绕过这些验证。

### 3.4 任务契约：`ct.job`

| 字段组 | 内容与校验 |
| --- | --- |
| 身份与提交 | 主机生成 `jobId`，`idempotencyKey` 标识一次提交；同键同内容返回原任务，同键异内容拒绝。重新计算使用新任务 ID，`retryOf` 可关联前次 |
| 固定输入 | 数据集 ID/修订和清单哈希、插件版本/包哈希、可选模型版本/哈希；运行前再核对，不接受排队后被替换的文件 |
| 配置 | `effectiveParameters` 固化默认值；`requestedResources` 与主机准许的 `resourceBudget` 区分；输入绑定与主机分配的独占输出根 |
| 生命周期 | `state`、`stage`、创建/启动/结束时间、阶段进度、心跳、错误和取消请求；计算状态独立于扫描 `phase` |
| 溯源 | 随机种子（适用时）、解释器/库/backend/驱动版本、硬件概况、日志引用、警告和结果清单引用；不能声称 GPU 必然逐位确定 |

建议状态顺序：`queued → validating → running → verifying → succeeded`；校验/执行/发布可进入 `failed`。未启动即可取消；运行中进入 `cancelling`，在进程树退出且清理/隔离临时输出后进入 `cancelled`。主机重启发现未结束任务标为 `interrupted`，不得自动重跑或冒充成功。

- 提交命令只做有界的请求检查并快速返回任务 ID；大文件校验在任务验证阶段异步执行。状态查询只返回有界摘要，事件用 `jobId + sequence + stage + timestamp` 去重和检测乱序。
- worker stdout 只输出版本化结构化事件，stderr 用于有界诊断；日志/进度限速、限长度、限总量。长阶段可报告未知总量，不伪造匀速百分比；worker 报告 100% 或退出码 0 都不等于主机成功发布。
- 启动超时、心跳超时、阶段无进展与总运行上限分别配置；取消先协作请求，宽限到期终止进程树（Windows Job Object 为候选，待验证），不能终止设备引擎。晚到的成功事件不得覆盖已接受的取消。
- 取消与发布由同一监督者串行裁决；发布提交点前接受取消则不发布，提交点后返回已完成。非法状态跳转、错误任务 ID 或重复终态事件不能更改权威状态。
- 算法失败仅更新计算任务及告警，不伪造采集故障/安全状态；STOP、关束、断开仍由原控制链处理，绝不等待算法取消完成。不存在调用设备的插件命令。

### 3.5 结果契约：`ct.result`

| 字段组 | 内容与校验 |
| --- | --- |
| 来源 | `resultId`、`jobId`、输入/校准修订与哈希、插件/模型身份、有效参数、环境和处理历史；明确参考坐标系及父产物 |
| 科学产物 | `artifacts` 中的 ID、类型、相对路径、字节/哈希、格式、shape/dtype/轴顺序、数值单位与 `valueMeaning`；科学体逻辑轴 `[z,y,x]`，物理向量分量 `[x,y,z]` |
| 空间语义 | `spacingMm`、`originMm`、`direction`、`coordinateFrame`；物理位置为 origin + direction × diag(spacing) × [x,y,z]，origin 是第一个体素中心；三者不得与文件头矛盾 |
| 派生产物 | 展示体、缩略图、网格各引用科学父产物及降采样/分割变换；标签有类别 ID/背景/未知约定，概率有类别轴、范围及是否归一化说明 |
| 质量与发布 | `qualityWarnings`、检查报告、完成时间和 `publicationState`；worker 仅提供候选结果，主机校验后的发布记录才是成功依据 |

科学体数据必须保留用于重新分析的精度和空间语义；渲染降采样不是定量数据源，STL 等网格也不能替代体数据。未验证绝对衰减尺度时标为 arbitrary_unit；即使按 1/mm 输出也需说明标定和多色性限制。未经校准不得标 HU、密度或材料成分。

结果先写任务私有临时区域；主机核对清单、允许的文件、可解码性、维度/方向/单位、有限值及哈希，再发布到唯一结果位置。禁止覆盖旧结果或源采集。发布临时区与目标应在同一受支持的文件系统；Windows 下关闭句柄后的重命名、杀毒软件占用、目标冲突、掉电/重启恢复须实测，不承诺任意跨卷“原子移动”。发布记录与任务日志不能假定跨文件事务原子性；重启时对账，只有完整且验证通过的提交记录才能恢复为成功，其余隔离并标记中断。

以下是字段级评审用例，不是完整可执行 JSON，所有 ID、版本和几何数值仅用于合成测试，不是本机设备参数。实施时须补齐全字段正/反例并交给正式 schema 和语义校验器验证。

| 契约 | 符合约定的正例 | 缺字段/冲突反例 | 不兼容反例 |
| --- | --- | --- | --- |
| 数据集 | 合成平行束数据 `phantom-parallel` 修订 1：180 个 `[v=64,u=64]` float32 线积分投影；角度按 kπ/180 明确关联（k=0…179）；1 mm 有效采样、完整坐标/索引和前向投影来源；所有文件验证通过，插件接受合成线积分输入 | 换成锥束但缺源位置/有效像素/几何校准：`GEOMETRY_REQUIRED`；标为 intensity 却直接送入只接收 line_integral 的插件：`INPUT_STAGE_MISMATCH` | `schemaVersion=2.0`，主机只支持 1.x：`SCHEMA_UNSUPPORTED` |

| 错误类别 | 代表码 | 行为 |
| --- | --- | --- |
| 数据未就绪 | `DATASET_INCOMPLETE`、`CALIBRATION_REQUIRED`、`DATA_CORRUPT`、`GEOMETRY_UNSUPPORTED` | 阻断并指出缺项；不自动采集校准、不补典型几何 |
| 语义/配置错误 | `INPUT_STAGE_MISMATCH`、`PREPROCESS_ALREADY_APPLIED`、`PARAMETER_INVALID`、`MODEL_INCOMPATIBLE` | 不启动计算；修正输入或产生新修订后重新提交 |
| 权限/路径 | `PLUGIN_UNTRUSTED`、`PATH_OUTSIDE_ROOT` | 拒绝执行/发布；不能通过另一个路径或隐式安装绕过 |
| 资源与运行 | `RESOURCE_UNAVAILABLE`、`DISK_FULL`、`PLUGIN_FAILED`、`JOB_TIMEOUT` | 保留失败原因，隔离部分输出；不自动换算法或无限重试 |
| 产物/恢复 | `OUTPUT_INVALID`、`PUBLISH_FAILED`、`JOB_INTERRUPTED` | 不标成功；重试是新任务，已发布结果保持不变 |

取消用任务终态 `cancelled` 表达，不伪装成插件错误或成功。`retryable` 只用于提示，不能授权自动运行插件或设备。

## 4. RAW、校正与算法选型门槛

### 4.1 固定初期处理链

原始 NEF → 经验证的线性强度 → 平暗场归一化 → 负对数投影 → 重构体 → 可选分析。已经是线积分的输入跳过已完成步骤；流水线依据类型和历史决定，不根据文件后缀或用户重复点击重新校正。

| 阶段 | 需要明确和保存的决策 | 阻断条件 |
| --- | --- | --- |
| NEF 解码 | RAW 解码器/版本、压缩与位深、Bayer/通道处理、黑电平/白电平、坏点和有效 ROI；禁止隐式 gamma、自动亮度、白平衡或照片增强；保留解码参数 | 未能证明输出与入射响应的线性关系；当前相机格式不受支持 |
| 探测成像映射 | 如通过闪烁屏/镜头采集，标定有效像素、镜头/屏幕畸变、ROI 到探测器坐标的变换；选取通道或去马赛克策略须有实验证据 | 直接把相机感光元件像元当有效探测器像元，或畸变未知且超出方法容许范围 |
| 暗场/平场 | 引用对应曝光/增益、能谱设定、温度等已知条件；记录多帧合成方法及漂移策略；科学数据与暗平场走一致解码路径 | 缺失必需校准、条件不匹配或无依据缩放校准 |
| 强度归一化 | 计算透射率 T=(I−D)/(F−D)，保留有效掩膜与异常比例；相机黑电平校正与实测暗场含义必须区分，避免重复扣除 | F−D 非正、饱和、坏点或低信号比例超过预先约定门槛 |
| 负对数 | p=−ln(T)，记录阈值、掩膜/插值策略和被处理比例；T≤0 无有效对数，T>1 可能来自噪声/漂移，不静默全部裁到 1 | 无约定的异常处置、对 line_integral 再取对数、输出非有限值 |
| 其他校正 | 环伪影、束硬化、散射校正逐项作为可追踪步骤，说明假设与适用样品；不宣称取负对数已消除多色性影响 | 校正改变物理含义却不更新语义/来源，或重复应用不支持的步骤 |

异常策略和容差由数据验证与基线实验确定，不在草案中编造生产阈值。手动放宽必须成为新的有效参数和警告，不能把未满足的物理前提改标为已满足。校准数据缺失时只提示所需证据，本模块不发起拍摄、转动或开束。

### 4.2 默认重构算法选择矩阵

原预留说明中“默认 FBP”调整为按真实几何选择，尚未锁定具体默认算法。

| 方法 | 适用条件 | 需要检查的局限 | 当前结论 |
| --- | --- | --- | --- |
| FBP 基线 | 平行束、已知像素/角度/旋转中心；按断层几何逐层或对应实现重构 | 不能把明显锥束的相机投影直接当作平行束；扇束须专门实现或有依据重排 | 若实测支持平行束模型，再评估 |
| FDK 基线 | 已校准圆轨迹锥束、完整支持的扫描角度范围和探测器几何 | 属近似方法；大锥角、截断、偏置轨迹等受实现限制；短扫描需明确覆盖与加权条件，不能只凭投影数判断 | 若实际为圆轨迹锥束，优先评估；不是已选定依赖 |
| SIRT/CGLS 等 | 可匹配几何的前向/反向投影器及收敛参数 | 计算/内存成本和噪声、正则化策略；稀疏角度不能保证唯一恢复真实结构 | 第二阶段候选，不首轮同时铺开 |
| 学习型方法 | 有明确训练域、模型结构、权重、输入规范和验证集 | 域偏移、伪结构和不确定性；不能以视觉平滑替代科学准确性 | 作为后续插件，不取代未验证的物理基线 |

算法匹配必须包含束型、轨迹、角覆盖、截断、输入阶段、资源及模型适用域。发现无匹配算法就阻断；不能为了提供默认项偷偷选择近似错误的几何。

## 5. 自定义模型与材料扩展

### 5.1 三类对象分离

| 对象 | 职责 | 接入限制 |
| --- | --- | --- |
| 算法插件 | 算法代码、网络构造/运行器、输入输出适配及参数约束 | 独立运行，通过统一任务协议；特殊算子/新网络用完整插件封装 |
| 已训练模型包 | 模型 ID/版本、权重及哈希、匹配的插件/适配器版本、张量布局/dtype/shape、输入归一化、输出解释、训练域与许可 | 只接受匹配适配器；禁止自动执行附带脚本或不受控反序列化；ONNX 等格式仍需解析器版本和资源验证 |
| 本次运行参数 | 滤波核、输出网格、迭代次数、阈值等有效配置 | 验证、冻结、写入溯源；训练学习率/轮次不等于训练后权重 |

模型包是插件/任务契约引用的受版本控制附件，不新增独立调度权威。适配器约定至少包括 batch/channel/spatial 轴、通道物理含义、单位、padding/重采样、可变尺寸、输出空间变换、类别表、背景与 unknown 标签、概率/置信度语义及适用范围。体数据重采样后标签/概率必须能映射回声明的物理坐标；标签不能默认使用会混合类别的线性插值。

标准接入路线是“适配器 + 符合张量规范的模型包”；自定义路线是“完整算法插件 + 可选模型包”。都通过同一就绪检查、任务监督和结果校验。不承诺仅拖入 `.pth`、`.onnx` 或训练配置就能运行；模型文件可能包含不可信内容，不能因为后缀看似标准而跳过信任检查。

初期采用外部训练、App 内推理与结果比较。记录训练数据说明/许可、适用材料与能谱、验证指标、已知局限和模型不确定性，不复制敏感训练样本。未来若增加训练，另行定义数据/标签拆分、防数据泄漏、评估和资源生命周期；不能把推理任务改名当作训练平台。

### 5.2 材料分类不等于物理材料分解

- 重构后分割/材料分类可消费科学体，产出标签或概率体；必须声明训练域、类别含义和无法判断时的 unknown 行为，不能强制给每个体素确定材料。
- 单能灰度受能谱、密度、束硬化和重构处理影响，不保证唯一确定材料；物理材料分解通常还需要多能量/能谱信息、校准或额外先验。当前采集契约没有证明这些条件已成立。
- 后续多能量扩展通过命名输入端口绑定各数据集，显式要求能量条件、配准关系、空间一致性和校准；不能把重复普通扫描冒充多能量数据。
- 保留科学体和处理历史，先对比物理基线再评估学习模型。材料结果不能回流为设备控制或安全判断依据。

## 6. 执行、安全与最小闭环边界

### 6.1 所有权和资源隔离

保留 React → Tauri → `ct-engine` 的调用关系。拟由 `ct-engine` 内唯一计算任务监督者持有任务状态，外部 worker 执行重计算；Tauri 仅负责已有桌面能力/转发，UI 只消费状态和引用，不推进任务。任务监督只是未来职责设计，不是本轮创建的服务或新进程目录。

- 默认只允许一个计算任务，且与生产采集不并发。引擎在开始扫描/开始计算两个方向检查互斥，未知控制状态不视为就绪；无需为重构旧数据强制连接真实设备。具体离线/在线状态门禁在后续 IPC 设计中评审。
- 不复用采集 `phase`；输入验证、校验和、进程等待、输出校验都不能持有扫描/设备锁或阻塞命令处理。资源耗尽时仍需保留控制线程预算；算法退出、取消、日志洪泛不得触发传输层超时后误杀设备 sidecar。
- 设备 STOP/关束/断开与算法取消是不同命令，设备命令永远不依赖算法响应。软件隔离不能替代现场屏蔽、联锁、急停和操作规程。
- 虚拟环境只隔离依赖，不隔离权限。首版仅允许人工信任的本地插件；无设备 API、只读输入、独占输出是协议约束，在同用户原生进程下不能宣称已防止恶意文件/串口访问。不可信插件必须另行设计并验证操作系统级隔离。
- 路径检查覆盖绝对路径、`..`、UNC/设备路径、重解析点/junction、符号链接及 Windows 名称别名；仅字符串前缀比较不够。解包限制文件数/解压大小、拒绝越界成员，检查后使用阶段仍要考虑路径替换风险。不得继承设备句柄、无关凭据或不必要的环境变量。
- 依赖安装、联网下载、执行第三方代码均为单独确认动作，不在扫描文件夹时自动触发。结果不得包含越界引用；取消/清理仅作用于本任务主机登记的临时根，不能递归清理用户源目录。
- 日志用任务 ID、插件 ID、阶段、错误码和短摘要定位，默认脱敏绝对路径和环境信息；不记录完整投影、模型权重或凭据。故障证据与科学结果分开保存，保留策略不得删除已发布结果。

## 7. 性能预算与可观测性评审

设 P 为投影数、D 为每张像素数、V 为体素数、b 为每个元素的字节数、K 为迭代次数：

- 逐像素预处理约 O(PD)；直接反投影通常约 O(PV)，还需计入滤波和数据搬运；迭代法粗略随 K 倍投影/反投影成本增加，具体以实现实测为准。
- 全量投影至少占 bPD，体数据至少占 bV；实际还包括解码/滤波缓冲、模型、临时体和库工作区。不能按最终文件大小推断峰值内存，也不能保证压缩输入能直接在显存内处理。
- 作为容量算例，float32 的 512³ 体约 0.5 GiB，1024³ 体约 4 GiB；这仅是单份数组，不是整机或显存最低要求。
- 提交前估算 RAM/VRAM、临时磁盘和最终结果空间，预留控制进程及系统余量；运行时监控峰值、阶段耗时、I/O 吞吐和剩余磁盘。估算不是硬限制，强制限制需执行器/操作系统支持并验证。
- 解码/预处理可优先流式处理；重构分块必须由 backend 明确支持并验证边界一致性。显存不足时阻断或让用户显式选择更低分辨率的新参数，禁止偷偷降采样科学输出。
- 科学体只通过文件/受控数据服务消费，UI IPC 仅携带 ID、状态、路径和有界元数据；预览另设体积/分辨率预算。不得把逐帧大清单和完整日志反复塞入设备快照。
- 初始实现需在目标机器测出并冻结：提交/查询延迟预算、STOP 路径允许开销、进度限速、日志限额、取消宽限、RAM/VRAM 峰值、磁盘峰值和预览预算。目前均待测，不能宣称达到实时性能。
