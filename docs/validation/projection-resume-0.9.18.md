# 0.9.18 / 0.9.19 投影断点与参考恢复修复

## 原因与修复范围

`start_scan` 原先统一发布 `preDark` 启动阶段，扫描线程随后无条件走前参考与装样流程。完整参考组自身会跳过已采照片，但已有投影的恢复仍写回 `placeSample` 并等待装样确认，造成恢复流程退回准备阶段。

启动快照与线程现在共用恢复阶段映射；已验证的投影/收尾断点跳过准备流程，从下一未提交投影继续。`load_resume` 完成冻结 profile、射线设定、几何、帧大小与 SHA-256 核对后，对有投影的历史 `placeSample` 清单仅作内存阶段修正，不直接改写历史清单或照片。首次装样和未完成参考采集保留对应确认。

恢复窗口不再把 HOME 排成必做步骤。确认机械/样品位置未变化的恢复可复用有效参考；已 STOP 的参考需要新 Nano 2.1.1 候选固件广告 `RESTORE_REFERENCE`。PC 在关束确认、参数和文件核对、计数对应末张/下一张相位后才发送命令，控制器重查当前计数并仅恢复参考标志，不写计数、不发 STEP。确认仍在最近一次 HOME 精确原点是独立确认项，必须有0计数和当前 Hall；不会自动把任意0计数或 Hall 当成回零完成。旧2.1.0固件不支持时仍阻塞，禁止静默运行 HOME。

## 验证与证据

- 离线门禁包含真实扫描协调器的脚本设备回归：正常投影断点、历史错误装样阶段、已进入投影但尚无投影文件、收尾断点；验证无参考/装样提示、只捕获缺失投影、既有照片/记录与参考哈希保持一致。真实未确认装样断点仍等待确认且不开束、不拍摄。
- Rust workspace、前端/桌面合同、类型检查、构建、模块图谱及 MSI 内程序启动/退出验证记录保存在 `.cache/tests/ct-engine/20261009-reference-resume/` 与 `.cache/tests/release/0.9.18/`。
- 用户授权的真实 task3 恢复过程单独记录在 `.cache/tests/desktop/20261009-task3-resume/`。实机通过须有新提交投影、文件哈希、原有 183 张投影记录及 20 张参考保留证据；仅显示 Running 不算通过。候选包从 MSI 提取运行，不等同于安装或硬件全面认证。
- 新固件源基于原2.1.0候选，只添加有界、无运动的参考恢复能力及2.1.1/20261009身份；原STOP、FAULT和HOME的失效安全规则保留。AVR编译结果 flash13992 bytes、RAM1476 bytes；实际固件源码的host harness通过1170项检查，包括错误计数、活动运动、警告ON与无心跳拒绝以及恢复不发脉冲。证据在 `.cache/tests/turntable/20261008-175718-candidate-avr-build/` 与 `20261008-175727-candidate-host-harness/`。这些均为离线证据，烧录和实机恢复需本次明确授权后另记。

## 未改变的边界

恢复仍须预检、必要的受控 HOME、当前相机冻结参数及原始文件完整性验证。OFF 未知、设备失联、曝光证据不完整、孤立文件与哈希不符仍拒绝或执行失效安全清理。一个 NEF 不证明一次物理曝光；跨 HOME 物理配准、完整扫描和定量重构精度需独立验收。软件恢复不替代现场屏蔽与联锁。

0.9.17 原安装程序及其签名、哈希保持不变；本次修复使用新的 0.9.18 版本分配。

0.9.19明确恢复确认文案：控制器若复位，只能走操作员确认仍在最近一次已完成HOME精确原点的独立确认，不把任意零计数当作原点。0.9.18已签名候选和验收记录保留，最终交付0.9.19；参考恢复固件内容与已校验的2.1.1候选相同。0.9.18实机只读检查确认COM7旧固件参考失效、0脉冲/Hall active及Moxtek OFF，未执行HOME、MOVE或采集；应用和引擎正常关闭，exit0。183张投影和20张参考的只读全文件核对记录保存在task3恢复目录。烧录授权及新提交投影是实机续测剩余门禁。
