# 3Dview 日系微缩沙盒设计稿

本设计只改变只读 3D 场景及其静态降级图。`ct-engine` 继续独占扫描、设备和安全状态；场景只消费已确认的角度与输出状态，不向设备发送命令。

## 视觉概念

把圆形滑轨、转台、相机和射线源放在一块有限的桌上微缩庭园里。设备仍是主角，草地、三棵低多边形小树、灌木、石子与单盏路灯只占轨道外缘。造型采用圆角大块面、浅米白外壳、灰绿机械件与少量珊瑚色握把；警告符号、光路方向、镜头、射线窗口和剪叉升降台仍清楚可辨。

- **Light：** 奶油白底座、柔和草绿与日光；背板保持低对比，设备边缘和光轴可读。
- **Dark：** 蓝灰底座和夜色背景；一盏路灯只形成局部、低强度暖色光池。灯光是环境装饰，不暗示射线已开启或现场安全。
- **镜头：** ISO、FRONT、TOP 使用正交投影和同一沙盒；投影包围盒参与自适配，顶部操作坞和底部读数保留空间。重复点击预设复位手动轨道视角。

## 物理与交互边界

- 光学组件中心线沿 `x=0, y=30`；射线源、样品、闪烁体与镜头的相对位置以 `scene-config.ts` 为准，不用装饰性位移改变光路。
- 轨道半径为 405，最外缘为 432；园景从半径 465 之外开始。树木与路灯不进入轨道、转台或光路空间。
- 相机和射线源本体尺寸、剪叉臂、丝杆、手轮、底板与四角滚轮保留原有机构关系；卡通感主要来自材质和小半径圆角。
- 每台车的四个承重轮分别压在半径 382 与 428 的两条同心跑道顶面；轮轴沿轨道径向，轮胎沿轨道切线滚动。内外侧导轮贴住轨道侧壁，轮轴支架接回同一车架底板，形成可沿圆轨滑行的受约束机构。相机车的承重轮通过底板两端的连接臂承托，不得画成与车架分离的四个独立轮座。
- 灰模验收必须在 ISO、FRONT、TOP 三视角看到轨面、轮胎接触点和车架承力路径；单一视角的轮轨重叠不算接触证据。若生成效果图把车架或轮组放到轨道旁，只作为被淘汰的构图研究，不作为 Three.js 造型依据。
- 角度动画仍只从设备确认的位置样本更新；未知、失联或停止清理中不把目标角度当成当前位置。扫描进度、Pause、Stop 和关束读回由引擎给出，场景不自行推进。
- WebGL 不可用时使用同主题的静态沙盒图。静态图用于识别设备布局，不表现实际转台姿态；准确角度仍以引擎读数为准。

## 参考与下一轮方向

参考 `前端素材/3Dreview` 的微缩城市、圆角分件、日夜光影和视频里的独立部件装配流程。视频的写实街景密度与透视镜头不适合直接搬入控制台。

本轮已通过 DSH 侧图像脚本（`gpt-image-2.5`，走 Responses API 的 hosted image tool 路径）生成了一张材质与光照研究图，并由人工查看后只采纳其明暗、材质与接触阴影线索；它的轮轨结构被明确否决，未用于任何几何判断。

**生成图不得作为几何或安全证据。** 已知被否决的画法包括：把相机/射线源小车画成独立于轨道的大轮组与长斜支架、把四个承重轮画成与车架分离的独立轮座、以及单条带枕木的铁路轨道（本项目真实几何是半径 378–386 与 424–432 的两条同心承重跑道）。几何依据只有 `scene-config.ts` 源码与 `docs/shots/2026-09-24-3dview-rebuild/` 下的原始 WebGL 渲染截图。相机镜头直接朝向样品；概念图中不画相机前的闪烁体或独立探测板。

动态图形仍须遵守只读反馈与安全颜色语义：姿态只随设备确认样本更新，束流视觉只认已确认输出，减少动态偏好要显式覆盖场景内的插值与阻尼。
