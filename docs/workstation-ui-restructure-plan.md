## 3. Camera 常驻栏

### 常驻内容

1. 顶部设备发现/明确选择/连接或断开，连接状态与型号；未知/失联/清理未确认明确显示。
2. 图像存储根目录及选择按钮。
3. ISO、原生快门档位（同时显示曝光时间）、光圈、白平衡下拉。
4. 紧凑显示当前曝光模式、Auto ISO、对焦模式，以及“单拍就绪”和“扫描固定配置就绪”各自的状态。
5. Read、Apply and verify、Single capture、Start/Stop Live View；已支持的对焦入口合理安排。
6. Advanced Settings 打开完整配置和预设，不在常驻栏展开全部34项候选。

### 参数事实来源

- 草稿 → 明确 Apply → 串行写入/实际读回继续保留；基本栏和 Advanced 使用同一份会话草稿、同一次 Apply 结果。
- 确认值、目标值、未知、错误必须区分。未 Apply 的草稿不能被用于扫描或被显示为已生效。
- 支持/只读/当前无效及选项禁用继续来自引擎 descriptor 与依赖结果；UI 不自己猜型号或自动模式。
- 相机快门是曝光目标的唯一编辑入口。扫描 `exposureMs` 按确认的原生快门及属性码精确派生，不保留第二个可写 Exposure 框、不四舍五入原生档位。
- 首次连接可把已确认实际值载入草稿，不写设备；后续物理变化与目标不一致会失效预检，不能静默覆盖用户目标。
- Advanced 保留其他已实现参数、标签、预设保存/导入/导出/比较及诊断。预设仍只包含相机配置，不包含存储路径、任务、射线或转台命令。
- 机身拨盘、硬件 MF 等当前只读设置，弹窗明确指出需要在机身/镜头调整，不能通过草稿绕过。

## 4. 扫描与独立单拍必须分开判定

### 4.1 扫描固定策略

由引擎实现并在预检、扫描开始、恢复及拍摄事务校验，不能只在 React 禁用按钮。

| 项目 | 扫描要求 |
| --- | --- |
| 曝光 | M 模式；原生定时快门、ISO、光圈已 Apply 并读回，未知/漂移拒绝 |
| Auto ISO | 关闭 |
| 对焦 | 已确认的硬件 MF 或软件 MF；不在投影之间触发 AF |
| 白平衡 | 固定档位或固定色温/固定手动预设；拒绝实际支持的 Auto 白平衡 |
| Active D-Lighting | D7100物理适用，必须鲜读原生OFF=4；未广告/读失败仍UNKNOWN并阻塞 |
| HDR、长曝光降噪、曝光延迟 | OFF，沿用确证的型号编码；HDR仅未广告时可用已确认NEF互斥证明，已广告ON/error/矛盾仍拒绝 |
| 图像与记录方式 | 当前已实现的 D7100 RAM、NEF、单张；RAW位深、压缩、裁切及其他相关值确认并冻结 |
| 包围 | 当前广告D0C0、严格UINT8 descriptor、鲜读OFF=0才可认定关闭；D1B1是曝光表读数，不是BKT |
| 多重曝光及其他自动/多帧选项 | D7100多重曝光物理适用但无可靠PTP OFF编码，UNKNOWN阻真实扫描；不猜码、不自动清除、不用人工确认当机器OFF |

自动模式按有证据的设备语义分类，不能凭选项标签包含“Auto”就一概判断。未支持项仍灰禁；若固定性验证必需的信息未知，返回明确阻塞，不能把未知当 OFF。

当前实现冻结profile5和固定策略版本2；旧profile1–4保持原canonical/hash及只读重构，拒绝续扫。上述C0/ADL/HDR门禁已有离线回归，多重曝光UNKNOWN使真实扫描仍BLOCKED；不会因为规划列项或旧P0有一个RAM文件而标记物理采集已完成认证。primary依据见[能力矩阵索引](architecture/native-camera-capability-matrix.md#依据索引)。

预检弹窗列出“项目 / 当前实际值 / 要求 / 如何修改”。可跳转基本栏或 Advanced；关闭弹窗不解除阻塞。操作员明确选择并 Apply 后重新读回、重新预检；不默认替用户选择 ISO、光圈或色温。

### 4.2 独立单拍允许自动参数

- 独立单拍不套用扫描的 M、Auto ISO OFF、固定 WB、MF 等整套限制。根据设备已验证能力允许自动曝光/ISO/WB及已支持的对焦操作。
- 必须保留独立拍摄的身份、会话、RAM主机保存、当前支持文件格式、单张事务、事件/完整文件/hash、取消及清理门禁。
- 独立入口保证单个验证完整的host NEF输出，未承诺一次物理曝光。多重曝光UNKNOWN明确诊断但不单独永久禁用普通自动曝光/ISO/WB照片；90C0、一C101、关联C102、超时及多对象拒绝继续保持。
- Live View 开启时仍禁止拍摄，必须明确停止；不自动停预览、拍摄再恢复。
- 不因允许自动参数而开放未适配的 JPEG/多对象、Bulb、视频或未知 Nikon 操作。对焦策略按已验证命令与能力明确表达，不盲发操作。
- 需要独立的 capture admission/readiness、超时与事件处理：允许按模式变化的曝光字段不能被误判为扫描冻结漂移；记录介质、格式、数量、会话等关键条件仍严格校验。
- 有界等待及可靠曝光结束/文件确认继续保留；自动曝光时不能用拍摄前的快门值猜完成。照片实际使用的 ISO/曝光信息仅在文件元数据有证据时显示为实拍值。

这一步属于领域功能调整，不是单纯改变按钮禁用样式。

## 5. Turntable 常驻栏

- 顶部独立连接/断开和已确认状态。
- 实际角度/位置是否已知、HOME参考是否有效、IDLE/运动/锁定/清理状态。
- HOME、输入指定正向角度并旋转；保留已有必要相位控制时合理压缩，不增加逆向、微步、速度或任意多圈功能。
- 普通转动沿现有生产方向，正数输入、协议符号和到位/ticket释放不变。
- 最下面放预检按钮、预检状态和必要阻塞提示。预检作用于整套扫描，不被误称为“仅转台检查”。
- HOME 的射线 OFF读回与台架物理隔离条件保持；恢复所需受控 HOME 与普通手动 HOME 保留不同占用裁决。
- 未完成任务的恢复/放弃入口保留在任务菜单与预检相关区域；放弃必须清理确认并保留全部文件，不能解除未知清理锁。

## 6. 统一存储位置

相机栏编辑唯一主机根目录，使用已有 `Parameters.savePath` 或等价单一领域字段；不能另外维护相机根目录和扫描根目录两份值。它与相机 `recordingMedia` 是不同概念。

```text
所选根目录/
  任务ID/               # 原有扫描清单、投影和参考帧结构保持
  CameraCaptures/        # 独立单拍；唯一capture ID命名，原子不覆盖
```

- 保留现有扫描文件组织与哈希/断点/重构规则，不迁移或重写旧文件。
- 任务 ID 保留合法路径检查，并防止与 `CameraCaptures` 等保留目录冲突（Windows大小写不敏感）。
- 独立目录仍做规范化、别名/链接、扫描目录及其关联 manifest 的隔离检查；禁止覆盖扫描数据或把单拍计入扫描帧数。
- 仅设置根目录不要求任务 ID、投影数或射线设备；相机独立使用继续自主。
- 改根目录会失效当前新任务预检；未完成任务的冻结路径、ID和采集条件保持锁定。
- File/Open Image Folder、默认目录解析、重启载入及所有路径展示必须消费同一来源。

## 7. 预检前统一“扫描准备”窗口

### 内容

- 任务 ID。
- 总投影数，1–3600整数；角度步进由引擎按360/N计算。
- 最长连续出束时间，界面min、领域整数sec；保留既有上限和冷却策略。
- 只读展示相机根目录、最终任务目录和确认的曝光配置，不重复编辑路径/快门。
- 全部既有几何：SOD、物体到探测器距离、有效探测器宽度、X/Y偏移、镜像；规定方向、测量来源继续记录，不能迁移时漏字段。

### 顺序

```text
Run Preflight（转台栏或菜单）
  -> 扫描准备统一窗口
  -> 完整验证并原子提交准备草稿
  -> 相机固定参数鲜读/比较；冲突则列清单并阻止
  -> 全设备预检
  -> 必要的受控HOME
  -> 参考帧确认/前暗场/前空场
  -> 装样确认
  -> 正式投影
```

- 去掉预检成功后再次填写几何的重复窗口；保留参考帧和装样阶段的现场确认。
- 取消准备窗口不写入半套参数、不创建拍摄文件、不开始设备动作、不制造未完成任务锁。
- 菜单 Run Preflight 与常驻按钮复用同一个入口；恢复任务走冻结资料的专用确认/比较流程，不用新任务窗口覆盖原参数。
- 历史实施前缺口：当时预检自动停止LV并写快门/RAM/burst，扫描入口再次写曝光。当前已拆开：核心配置只由明确Apply写入；预检/启动/恢复鲜读比较，LV开启、自动参数、未知或漂移直接阻塞，不自动修复后宣称一致。
- 当前prepare guard持有提交中的窗口与请求：准备/预检未结算前禁关闭、Esc/遮罩关闭、跳转Advanced及其他菜单，Stop始终可用；Stop、会话/任务异常变化使旧请求失效，迟到结果不能关闭新窗口或继续预检。已提交完整任务参数保留，提交前取消不写入半套配置。对应[准备请求回归](../tmp/tests/frontend/20261005-100837-preparation-guard-regression/result.json)及[rc2验收](workstation-restructure-rc2-acceptance-2026-10-05.md)；这是请求所有权，不是第二份生产领域状态。
- Live View仍在使用时明确提示先结束；自动参数未修正、草稿未Apply、未知、读回差异都不能进入扫描。
- 射线参数、USB自动关断和恢复释放的独立确认继续按现有领域规则处理；不通过搬弹窗改变出束权限或把设定当实测。

## 8. 中央照片/Live View/3D显示

- 只覆盖中央3D内容区，栏目边界、全局状态与Start/Pause/Stop等安全入口保持可访问。
- 展示状态可为 Equipment / Result / Independent photo / Live；它是UI展示选择，不是第二份扫描或设备状态。
- Equipment/Result保留已有3D组件和姿态/结果数据；切换不发送设备运动或丢失确认状态。
- 独立单拍只在领域成功登记完整文件后展示；保持到操作员关闭/返回，然后切到Equipment。预览失败显示“文件已保存，预览不可用”，不能伪造图像。
- Live复用已有仅内存、会话/序号、新鲜度、STALE及有界两帧呈现。结束/Stop/断开/失联/取消撤下画面回Equipment；设备停止与清理是否确认仍单独显示，返回3D不等于硬件已安全停止。
- 关闭、替换、任务/会话变化使旧请求失效；迟到照片/实时帧/重构加载结果不能抢回显示区。
- 拍照预览需要保存完整 `CapturedImage` 登记：capture ID、会话、操作、大小、hash等。现有 `lastCapture` 路径不足以授予预览访问。
- 新预览IPC只接受capture ID，由引擎登记解析文件，Tauri核大小/hash并复用NEF内嵌JPEG提取；renderer不得传任意文件路径。没有可用内嵌JPEG时明确说明。
- Live不保存帧；独立NEF按明确拍摄保存；预览不另生成JPEG临时文件。

## 11. 兼容与安全边界

- `ct-engine`继续唯一持有设备、扫描、安全、任务锁与事务；React只持展示和未提交草稿。
- 新固定策略单独版本化并用于新采集；旧profile/hash的只读验证与重构不能被新限制破坏。
- 不符合新固定策略或缺少证明所需冻结证据的旧任务禁止追加；保留文件并明确说明原因。不通过自动改参数或重写旧profile使它看似可续扫。
- 必须满足的新策略、冻结值及已有协议全部吻合时，受控恢复仍按当前证据进行。
- 开束/OFF实测、再次开束间隔、连续出束上限、冷却、曝光结束与文件完成分离等原规则保持。
- 失联/超时/未知/清理未确认保持故障保护；操作队列、取消代次、迟到成功拒绝、断点锁不能因UI迁移放宽。
- 单拍、Live、普通运动不自动开束；扫描/暂停/收尾/恢复锁定仍由领域执行。
- 不修改数值重构、原始NEF或Nano固件，不增加模拟成功替代设备证据。

## 12. 验收清单

### 行为和领域

- 扫描自动/未知项返回结构化阻塞；仅关闭提醒不能启动。不可写的机身设置给实际修正办法。
- 预检、启动、恢复对核心相机参数写入计数为零；配置只在明确Apply动作写入并读回。
- 未Apply草稿、未确认值、预检后漂移均不能开始或续扫。
- 独立单拍可使用已支持的自动配置；仍要求LV OFF、合法单张主机NEF和可靠完成/文件/hash，扫描参数及帧数不被改变。
- 独立单拍与扫描文件隔离，目录别名、保留名、已有manifest和不覆盖检查有效。
- 准备窗口取消无半提交、无拍照/运动/开束、无假任务锁；几何只填写一次。
- 扫描配置变化失效预检；恢复不自动修改参数匹配历史任务；旧数据只读验证和重构兼容。
- 单拍照片关闭、LV停止、断开、故障、Stop及迟到结果的中央视图和占用行为正确。
- 重构日志来自引擎，后台进度即使不在重构标签也能收到；切标签/重载不重复制造事件。

### 几何和视觉

- 在1920×1080基准核对本表全部边界，日志与运行状态顶/底差≤1个实际CSS像素；左两栏顶/底与Equipment/日志对齐。
- 栏目铺满客户区；1080p实际桌面客户区、2K/4K、DPI125/150/200/250%及已有较小窗口边界均验证。
- 所有状态下常驻控件完整可见；六个竖排标签完整可用；仅日志列表/图像条/浮层允许滚动。
- 最长路径、参数标签、FAULT/UNKNOWN/清理未确认、重构失败与按钮状态不裁掉关键信息。
- 照片/LV只覆盖3D内容区，Stop始终可用；画面不新建磁盘缓存。

### 必要命令及交付

`npm.cmd run impact`、`npm.cmd run typecheck`、`npm.cmd run test:sites`、`npm.cmd run module-map:check`、`cargo test --workspace`。

新增针对性回归覆盖固定策略/独立自动捕获/准备原子提交/预览登记/日志以及取消和恢复；更新原306px布局测试而非删除验收。

随后 `npm.cmd run candidate:build`，核对EXE与保留正式入口的哈希，实际Windows启动/正常关闭/布局检查。真实相机与转台必须唯一owner并记录独立硬件结果，射线/联动扫描另按授权验证。结果分别标记PASS/FAIL/BLOCKED；离线通过不标记硬件认证。
